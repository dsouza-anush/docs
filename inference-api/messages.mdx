title: "Messages API"
description: "Native Anthropic Messages API endpoint for Claude models with full SDK compatibility, extended thinking, and prompt caching."
---

The `/v1/messages` endpoint provides native Anthropic API compatibility for Claude models. If you're already using the Anthropic SDK, you can switch to Heroku AI by changing the base URL and API key—no other code changes required.

<Note>
  **Anthropic Models Only**: The Messages API is exclusively available for Claude models. For other models (Amazon Nova, Cohere, etc.), use the [Chat Completions API](/inference-api/chat-completions).
</Note>

## When to use Messages vs Chat Completions

| Use Messages API when... | Use Chat Completions when... |
|--------------------------|------------------------------|
| You have existing Anthropic SDK code | You need OpenAI SDK compatibility |
| You want native `cache_control` for prompt caching | You prefer header-based caching control |
| You're using Anthropic-specific features like `thinking` | You're using non-Anthropic models |
| You want to use the Anthropic Agent SDK (coming soon) | You need multi-provider support |

## Base URL

```
https://us.inference.heroku.com
```

## Authentication

Unlike the Chat Completions endpoint which uses `Authorization: Bearer`, the Messages API uses Anthropic's authentication pattern:

```bash
x-api-key: YOUR_INFERENCE_KEY
```

This matches the Anthropic SDK's expected authentication header.

## Quick Start

<CodeGroup>

```python Python (Anthropic SDK)
import os
from anthropic import Anthropic

client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)

message = client.messages.create(
    model=os.getenv("INFERENCE_MODEL_ID"),
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Hello, what should I build today?"}
    ]
)

print(message.content[0].text)
```

```javascript JavaScript (Anthropic SDK)
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: process.env.INFERENCE_KEY,
  baseURL: process.env.INFERENCE_URL,
});

const message = await client.messages.create({
  model: process.env.INFERENCE_MODEL_ID,
  max_tokens: 1024,
  messages: [
    { role: "user", content: "Hello, what should I build today?" }
  ],
});

console.log(message.content[0].text);
```

```bash cURL
curl https://us.inference.heroku.com/v1/messages \
  -H "x-api-key: $INFERENCE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-4-sonnet",
    "max_tokens": 1024,
    "messages": [
      {"role": "user", "content": "Hello, what should I build today?"}
    ]
  }'
```

</CodeGroup>

## Request Parameters

### model
**string** · required

The Claude model to use. Use your `INFERENCE_MODEL_ID` config var value.

Supported models: `claude-4-sonnet`, `claude-3-7-sonnet`, `claude-3-5-sonnet`, `claude-3-5-haiku`, `claude-3-haiku`

### max_tokens
**integer** · required

The maximum number of tokens to generate. Unlike Chat Completions where this is optional, the Messages API requires this field.

### messages
**array** · required

Array of message objects. Each message has a `role` (`user` or `assistant`) and `content`.

```json
[
  {"role": "user", "content": "What is Heroku?"},
  {"role": "assistant", "content": "Heroku is a cloud platform..."},
  {"role": "user", "content": "How do I deploy to it?"}
]
```

<Note>
  The Messages API uses `user` and `assistant` roles only. System prompts are passed separately via the `system` parameter.
</Note>

### system
**string or array** · optional

System prompt that sets the assistant's behavior. Can be a string or an array of content blocks (for prompt caching).

```json
{
  "system": "You are a helpful Heroku expert.",
  "messages": [...]
}
```

### temperature
**float** · optional · default: `1.0`

Controls randomness. Range: `0.0` to `1.0`.

### top_p
**float** · optional

Nucleus sampling threshold. Range: `0.0` to `1.0`.

### top_k
**integer** · optional

Only sample from the top K options for each token.

### stop_sequences
**array of strings** · optional

Custom strings that cause the model to stop generating.

### stream
**boolean** · optional · default: `false`

Enable streaming responses via server-sent events.

### metadata
**object** · optional

Metadata about the request. Includes `user_id` for tracking.

```json
{
  "metadata": {
    "user_id": "user_123"
  }
}
```

### thinking
**object** · optional

Enable extended thinking for Claude 3.7 Sonnet and Claude 4 Sonnet. The model uses additional internal reasoning steps before responding.

```json
{
  "thinking": {
    "type": "enabled",
    "budget_tokens": 5000
  }
}
```

**Fields:**
- `type`: `"enabled"` to activate extended thinking
- `budget_tokens`: Token budget for reasoning (minimum 1024)

<Warning>
Extended thinking is only available for Claude 3.7 Sonnet and Claude 4 Sonnet.
</Warning>

### tools
**array** · optional

Tools the model can use. Follows Anthropic's tool format.

```json
{
  "tools": [
    {
      "name": "get_weather",
      "description": "Get current weather for a location",
      "input_schema": {
        "type": "object",
        "properties": {
          "location": {
            "type": "string",
            "description": "City name"
          }
        },
        "required": ["location"]
      }
    }
  ]
}
```

### tool_choice
**object** · optional

Controls how the model uses tools.

- `{"type": "auto"}` - Model decides whether to use tools
- `{"type": "any"}` - Model must use at least one tool
- `{"type": "tool", "name": "tool_name"}` - Model must use the specified tool

## Response

```json
{
  "id": "msg_01XYZ...",
  "type": "message",
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "Hello! Here are some ideas for what you could build today..."
    }
  ],
  "model": "claude-4-sonnet",
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 25,
    "output_tokens": 150
  }
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Unique message identifier |
| `type` | string | Always `"message"` |
| `role` | string | Always `"assistant"` |
| `content` | array | Array of content blocks (text, tool_use) |
| `model` | string | Model that generated the response |
| `stop_reason` | string | Why generation stopped: `end_turn`, `max_tokens`, `stop_sequence`, `tool_use` |
| `usage` | object | Token usage statistics |

## Prompt Caching

The Messages API supports Anthropic-style prompt caching via `cache_control` blocks. This differs from Chat Completions, which uses a header to enable/disable automatic caching.

### How It Works

Add `cache_control` to cacheable content blocks:

```python
from anthropic import Anthropic

client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)

# Cache a large system prompt
message = client.messages.create(
    model="claude-4-sonnet",
    max_tokens=1024,
    system=[
        {
            "type": "text",
            "text": "You are an expert on the Heroku platform...",  # Long system prompt
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[
        {"role": "user", "content": "How do I scale dynos?"}
    ]
)
```

### What Can Be Cached

- **System prompts**: Add `cache_control` to system content blocks
- **Messages**: Add `cache_control` to message content blocks
- **Tools**: Add `cache_control` to tool definitions

```python
# Cache tool definitions
message = client.messages.create(
    model="claude-4-sonnet",
    max_tokens=1024,
    tools=[
        {
            "name": "search_docs",
            "description": "Search the documentation...",
            "input_schema": {...},
            "cache_control": {"type": "ephemeral"}
        }
    ],
    messages=[...]
)
```

### Cache Behavior

- Cache entries expire after 5 minutes of inactivity
- Minimum content length required for caching (varies by model)
- Cache hits return faster and may have different pricing

## Streaming

Enable streaming for real-time responses:

<CodeGroup>

```python Python
from anthropic import Anthropic

client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)

with client.messages.stream(
    model="claude-4-sonnet",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Tell me a story"}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
```

```javascript JavaScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic({
  apiKey: process.env.INFERENCE_KEY,
  baseURL: process.env.INFERENCE_URL,
});

const stream = await client.messages.stream({
  model: process.env.INFERENCE_MODEL_ID,
  max_tokens: 1024,
  messages: [{ role: "user", content: "Tell me a story" }],
});

for await (const event of stream) {
  if (event.type === "content_block_delta" && event.delta.type === "text_delta") {
    process.stdout.write(event.delta.text);
  }
}
```

```bash cURL
curl https://us.inference.heroku.com/v1/messages \
  -H "x-api-key: $INFERENCE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-4-sonnet",
    "max_tokens": 1024,
    "stream": true,
    "messages": [{"role": "user", "content": "Tell me a story"}]
  }'
```

## Tool Use Example

```python
from anthropic import Anthropic

client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)

# Define a tool
tools = [
    {
        "name": "get_weather",
        "description": "Get the current weather for a location",
        "input_schema": {
            "type": "object",
            "properties": {
                "location": {
                    "type": "string",
                    "description": "City and state, e.g. Portland, OR"
                }
            },
            "required": ["location"]
        }
    }
]

# First request - model may call the tool
message = client.messages.create(
    model="claude-4-sonnet",
    max_tokens=1024,
    tools=tools,
    messages=[
        {"role": "user", "content": "What's the weather in Portland?"}
    ]
)

# Check if model wants to use a tool
if message.stop_reason == "tool_use":
    tool_use = next(block for block in message.content if block.type == "tool_use")

    # Execute the tool (your implementation)
    weather_result = get_weather(tool_use.input["location"])

    # Send tool result back
    final_message = client.messages.create(
        model="claude-4-sonnet",
        max_tokens=1024,
        tools=tools,
        messages=[
            {"role": "user", "content": "What's the weather in Portland?"},
            {"role": "assistant", "content": message.content},
            {
                "role": "user",
                "content": [
                    {
                        "type": "tool_result",
                        "tool_use_id": tool_use.id,
                        "content": weather_result
                    }
                ]
            }
        ]
    )

    print(final_message.content[0].text)
```

## Extended Thinking Example

```python
from anthropic import Anthropic

client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)

message = client.messages.create(
    model="claude-4-sonnet",  # or claude-3-7-sonnet
    max_tokens=8000,
    thinking={
        "type": "enabled",
        "budget_tokens": 5000
    },
    messages=[
        {"role": "user", "content": "Solve this step by step: If a train leaves..."}
    ]
)

# Response includes thinking blocks
for block in message.content:
    if block.type == "thinking":
        print("Reasoning:", block.thinking)
    elif block.type == "text":
        print("Answer:", block.text)
```

## Limitations

<Warning>
- **Anthropic models only**: This endpoint only works with Claude models
- **No `anthropic-beta` header**: Beta features accessed via this header are not currently supported
- **Agent SDK support coming soon**: Full Anthropic Agent SDK support will be available with a future Managed Inference plan update
</Warning>

## Migrating from Anthropic

If you're moving from Anthropic's API to Heroku AI:

```python
# Before (direct Anthropic)
from anthropic import Anthropic
client = Anthropic()  # Uses ANTHROPIC_API_KEY

# After (Heroku AI)
from anthropic import Anthropic
client = Anthropic(
    api_key=os.getenv("INFERENCE_KEY"),
    base_url=os.getenv("INFERENCE_URL")
)
```

All other code remains the same. Your messages, tools, and streaming logic work without modification.
